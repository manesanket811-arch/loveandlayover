## 🔑 Key Files Explained

### **1. `index.html` - Frontend Website**
- **What**: HTML/CSS/JavaScript website
- **Maintained by**: You (edit content, add destinations)
- **Update**: Edit locally, upload to S3, invalidate CloudFront
- **Git tracking**: ✅ Yes, commit all changes
- **Contains**: HTML, styles, JavaScript for interactivity

### **2. `template.yaml` - Infrastructure as Code**
- **What**: CloudFormation/SAM template defining all AWS resources
- **Maintained by**: You (when adding/changing AWS resources)
- **Update**: Edit, run `sam build && sam deploy`
- **Git tracking**: ✅ Yes, commit all changes
- **Defines**:
  - Lambda function
  - API Gateway endpoints
  - DynamoDB tables
  - S3 buckets
  - CloudFront distribution
  - IAM roles & permissions

### **3. `lambda_handler.py` - Backend Code**
- **What**: Python code running on AWS Lambda
- **Maintained by**: You (when adding features)
- **Update**: Edit, run `sam build && sam deploy`
- **Git tracking**: ✅ Yes, commit all changes
- **Handles**:
  - Email subscriptions
  - Contact form submissions
  - Itinerary downloads
  - Database operations

### **4. `requirements.txt` - Dependencies**
- **What**: Python packages needed by Lambda
- **Maintained by**: You (when adding new features)
- **Update**: Add package name, run `sam build && sam deploy`
- **Git tracking**: ✅ Yes, commit changes
- **Current**: boto3, botocore (AWS SDK)

### **5. `.env` - Configuration (DON'T COMMIT!)**
- **What**: Local environment variables
- **Maintained by**: You (your machine only)
- **Update**: Edit `.env` file locally
- **Git tracking**: ❌ NO - in .gitignore
- **Contains**: AWS region, bucket names, API endpoints
- **Why not commit**: Safety - credentials should never be in git

### **6. `.gitignore` - Git Security**
- **What**: Tells Git what files NOT to track
- **Maintains**: `__pycache__/`, `.env`, `*.pem`, `*.log`
- **Git tracking**: ✅ Yes, commit this
- **Important**: Prevents secrets from leaking

## 🔄 Deployment Workflow

### **Workflow: Make a Change → Deploy to AWS**

```
1. Make a local change
   └─ Edit: index.html OR template.yaml OR lambda_handler.py
   
2. Test locally (optional)
   └─ Open index.html in browser
   └─ Check Lambda code syntax
   
3. Commit to Git
   └─ git add .
   └─ git commit -m "description of change"
   
4. Deploy to AWS
   └─ sam build          (builds Lambda package)
   └─ sam deploy         (uploads to AWS)
   
5. Verify live
   └─ Check CloudFront URL
   └─ Test functionality
```

## 🚀 Making Changes - Examples

### **Example 1: Add New Destination (Tokyo)**

1. **Edit HTML** - Add destination card:
```html
<!-- In index.html, in the destinations section -->
<a class="gcard reveal" href="#contact" data-destination="tokyo" data-itinerary="food-tour">
  <div class="gtop t1"><span class="badge">🍜 Food</span><div class="days"><span class="nn">5</span><span class="dd">days</span></div></div>
  <div class="gbody"><h3>Tokyo Food Tour</h3><p>Ramen, sushi, and street food...</p><span class="link">Download →</span></div>
</a>
```

2. **Create PDF**:
```bash
# Create tokyo-food-tour.pdf using method from ITINERARY_CREATION.md
```

3. **Upload PDF**:
```bash
aws s3 cp tokyo-food-tour.pdf s3://love-and-layovers-itineraries-XXXX/tokyo/
```

4. **Commit & Deploy**:
```bash
git add index.html
git commit -m "Add Tokyo food tour itinerary"
aws s3 cp index.html s3://love-and-layovers-website-XXXX/
aws cloudfront create-invalidation --distribution-id E123 --paths "/*"
```

### **Example 2: Add New Feature (Email Notification)**

1. **Update Lambda** - Edit `lambda_handler.py`:
```python
def send_notification(email, destination):
    """Send trip notification email"""
    ses_client.send_email(
        Source='hello@loveandlayovers.com',
        Destination={'ToAddresses': [email]},
        Message={
            'Subject': {'Data': f'{destination} guide ready!'},
            'Body': {'Html': {'Data': '<html>...</html>'}}
        }
    )
```

2. **Update Requirements** - If using new package:
```bash
echo "requests==2.31.0" >> requirements.txt
```

3. **Deploy**:
```bash
git add lambda_handler.py requirements.txt
git commit -m "Add email notification feature"
sam build
sam deploy
```

### **Example 3: Change API Timeout**

1. **Edit Template** - In `template.yaml`:
```yaml
Globals:
  Function:
    Timeout: 60          # Changed from 30
    Runtime: python3.11
```

2. **Deploy**:
```bash
git add template.yaml
git commit -m "Increase Lambda timeout to 60 seconds"
sam build
sam deploy
```

## 🔒 Security - What NOT To Commit

**NEVER commit these files:**
- `.env` (has your config)
- `*.pem` or `*.key` (AWS credentials)
- `credentials.json` (AWS credentials)
- `__pycache__/` (Python cache)
- `.aws-sam/` (build artifacts)

**These are already in `.gitignore`** ✅

## 📊 AWS Resources Created by template.yaml

When you run `sam deploy`, this file creates:

| Resource | Name | Purpose |
|----------|------|---------|
| Lambda | love-and-layovers-api | Backend code execution |
| API Gateway | love-and-layovers-api | API endpoints (/subscribe, /contact, etc) |
| DynamoDB | love-and-layovers-subscribers | Store emails |
| DynamoDB | love-and-layovers-contacts | Store contact messages |
| DynamoDB | love-and-layovers-downloads | Track downloads |
| S3 | love-and-layovers-website-* | Store website files |
| S3 | love-and-layovers-itineraries-* | Store PDF itineraries |
| CloudFront | d*.cloudfront.net | Global CDN |
| IAM Role | SAM-APIFunctionRole-* | Lambda permissions |

**All managed by ONE file: `template.yaml`** 🎉

## 🔧 Common Maintenance Tasks

### **Update Website Content**
```bash
# 1. Edit index.html locally
nano index.html

open index.html

# 3. Upload to S3
aws s3 cp index.html s3://$WEBSITE_BUCKET/

aws cloudfront create-invalidation --distribution-id $DIST_ID --paths "/*"
```

### **Update Backend Code**
```bash
# 1. Edit lambda_handler.py
nano lambda_handler.py

# 2. Test locally (optional)
python lambda_handler.py

# 3. Deploy to AWS
sam build
sam deploy

# 4. Verify logs
sam logs -n APIFunction -t
```

### **Add New Infrastructure**
```bash
# 1. Edit template.yaml
nano template.yaml

# 2. Deploy changes
sam build
sam deploy

# 3. Check CloudFormation outputs for new resource names
aws cloudformation describe-stacks --stack-name love-and-layovers-stack
```

## 📈 Scaling Changes

### **If Traffic Increases**

The current setup auto-scales:
- ✅ Lambda - auto scales (handles more requests)
- ✅ DynamoDB - on-demand pricing (pays for what you use)
- ✅ CloudFront - auto scales (more locations if needed)

**No changes needed!** The serverless architecture scales automatically.

### **If You Want More Control**

You could modify `template.yaml`:
```yaml
# Add reserved capacity for DynamoDB
SubscribersTable:
  BillingMode: PROVISIONED
  ProvisionedThroughput:
    ReadCapacityUnits: 5
    WriteCapacityUnits: 5

# Add Lambda reserved concurrency
APIFunction:
  ReservedConcurrentExecutions: 100
```

## 🚨 Disaster Recovery

### **Backup Everything**
```bash
# Backup website files
aws s3 sync s3://$WEBSITE_BUCKET ./backup/website

# Backup itineraries
aws s3 sync s3://$ITINERARY_BUCKET ./backup/itineraries

# Backup database
aws dynamodb create-backup --table-name love-and-layovers-subscribers
aws dynamodb create-backup --table-name love-and-layovers-contacts
aws dynamodb create-backup --table-name love-and-layovers-downloads

# Backup code & config
git push origin main
```

### **Restore from Git**
```bash
# If you accidentally delete code
git log                          # See all commits
git show COMMIT_SHA              # See what was in that commit
git checkout COMMIT_SHA -- file  # Restore that file
```
